# M0. Monorepo'ga o'tkazish

Hozirgi loyiha (Next.js frontend) repo ildizida turibdi. Uni monorepo'ga aylantir: maktab365/ ichida frontend/ va backend/.

1) Fayllarni ko'chir (git tarixi saqlansin: git mv):
- Hozirgi butun frontend (src, public, package.json, lock fayl, configlar, .env.example, README, tests) → frontend/.
- brand/ papkasi ildizda qoladi (logo to'plami).
- Ildizda: .gitignore (python, node, env, docker, .next), .editorconfig.
- backend/ papkasi yarat (hozircha faqat README.md bilan; Django keyingi promptda).
2) Ildizdagi fayllar:
- CLAUDE.md: monorepo xaritasi, har papkaning vazifasi, "frontend/ va backend/ ichida ularning o'z CLAUDE.md fayli bor", shartnoma qoidasi (backend/openapi.yaml yagona manba, frontend API tiplarini qo'lda yozmaydi, o'zgarsa make schema && make types), API konventsiyalari (/api/v1, snake_case, xato formati, LocalizedText), rollar, "Bosqich tayyor mezoni" (Definition of Done): backend ruff+pytest yashil, make schema va make types ishga tushirilgan va commit qilingan, frontend typecheck+lint+test+build yashil, bosqichning smoke e2e testi o'tgan, README yangilangan.
- frontend/CLAUDE.md: mavjud CLAUDE.md shu yerga ko'chadi (yo'llar yangilansin).
- Makefile (ildizda): make dev (docker compose up backend servislari + frontend dev), make test (ikkalasi), make lint, make schema (backend OpenAPI yangilaydi), make types (frontend/src/lib/api/schema.ts generatsiya), make e2e. Backend hali yo'q bo'lsa tegishli target'lar "backend hali sozlanmagan" deb chiroyli xabar bersin.
- README.md (ildizda): loyiha tavsifi, struktura, ishga tushirish, har papkaga havola.
- .github/workflows/ci.yml: path filter bilan ikkita job (frontend/** o'zgarsa frontend job: install, typecheck, lint, test, build; backend/** o'zgarsa backend job — hozircha bo'sh skelet), ildiz fayllari o'zgarsa ikkalasi.
3) frontend/ ichida hammasi avvalgidek ishlashi shart: npm install, npm run dev, build, test. Barcha yo'llar (tsconfig, eslint, vitest, playwright, public/ va brand/ havolalari, README'dagi buyruqlar) yangilansin.
4) Deploy eslatmalari README'ga: Vercel'da Root Directory = frontend.
Oxirida: cd frontend && typecheck, lint, test, build yashil; git status'da faqat kutilgan ko'chirishlar. Bajarilganlar ro'yxatini chiqar.
