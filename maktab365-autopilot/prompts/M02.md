# M2. Foydalanuvchi va profil (backend) + onboarding/sozlamalarni haqiqiy API'ga

apps/accounts ni va frontenddagi profil oqimini birga qur.

BACKEND:
Modellar:
- User (AbstractBaseUser+PermissionsMixin, UUID pk): email (case-insensitive unique, NULL bo'lishi mumkin: Telegram orqali kirganda email bo'lmasligi mumkin), email_verified_at, password (ixtiyoriy: parolsiz akkaunt bo'lishi mumkin), is_active, is_staff, role (student|teacher|editor|admin), last_login, date_joined.
- Profile (OneToOne): display_name, avatar_url, locale (uz|uz-Cyrl|ru|en), grade (1–11), subjects (JSON), grades (JSON, o'qituvchi uchun), onboarded_at (null = onboarding tugamagan).
- Identity: user, provider (password|google|telegram|email_otp), provider_uid, email, verified, created_at; unique(provider, provider_uid).
- AuthEvent (audit): user, type, ip, user_agent, meta, created_at.
Qoidalar: parol validatorlari (min 8, umumiy parollar, faqat raqam emas), Argon2 birinchi hasher. Rol o'zgartirish faqat service funksiya orqali; oddiy foydalanuvchi faqat student<->teacher tanlay oladi, editor/admin ni faqat admin.
Endpoint'lar: GET/PATCH /api/v1/me/, POST /api/v1/me/onboarding/ (rol, ism, sinf yoki fanlar/sinflar; onboarded_at belgilanadi), PATCH /api/v1/me/role/, DELETE /api/v1/me/ (soft delete + anonimlashtirish), GET /api/v1/me/export/ (JSON).
Django admin'da User/Profile/Identity/AuthEvent qulay. Testlar: modellar, rol qoidalari, onboarding, o'chirish/anonimlashtirish, export. make schema.

FRONTEND:
- make types. HttpApi'ga getMe, updateProfile, saveProfile (onboarding), setRole, deleteAccount, exportData qo'sh (http rejimida haqiqiy API; mock saqlansin).
- Onboarding (/onboarding) va Sozlamalar sahifasi http rejimida backend'ga yozsin. Profil localStorage'dan emas serverdan o'qilsin. Rol/sinf almashganda mos panelga yo'naltirilsin.
- Sozlamalar → Hisob: ma'lumotni yuklab olish va akkauntni o'chirish (tasdiqlash dialogi bilan).
- Hozircha Auth.js Google bilan ishlayveradi; backend'da user hali yaratilmasligi uchun vaqtinchalik ko'prik: Google'dan kirgandan keyin POST /dev/... YO'Q — ko'prik yozma. Frontend profil endpointlari keyingi bosqichda (M3) tokenlar kelgach to'liq ishlaydi; shu bosqichda faqat tip, HttpApi metodlari va UI tayyorlanadi, mock rejimida ishlaydi, http rejimini Postman/httpie bilan emas, backend testlari bilan qoplanadi.
