# M14. Analitika va statistika

Kontent sifatini yaxshilash uchun oddiy statistika (kuzatuv emas).

BACKEND (apps/analytics):
- POST /api/v1/events/ (anon ham, batch max 50): faqat ruxsat etilgan turlar: topic_view, topic_read, exercise_answered{exercise_id, correct}, search{q, results_count}. Shaxsiy ma'lumot yo'q: anon uchun tasodifiy anon_id, IP saqlanmaydi. Throttle va hajm limiti.
- Aggregatsiya (Celery beat): TopicDailyStat, ExerciseStat (attempts, wrong_rate), SearchStat (normallashgan q, count, zero_results_count). Xom hodisalar 90 kundan keyin o'chadi (command + beat).
- Admin: GET /admin/stats/topics/ (eng ko'p ochilgan, eng kam o'qilgan), /stats/exercises/ (xato foizi yuqori mashqlar), /stats/search/ (natijasiz qidiruvlar), davr filtri.
Testlar: hodisa validatsiyasi, aggregatsiya, retention, anon ma'lumot yo'qligi. make schema.

FRONTEND:
- make types. Yengil event yuboruvchi (src/lib/analytics.ts): hodisalarni to'plab batch qilib yuboradi (sendBeacon/fetch keepalive), foydalanuvchi sozlamasi/DNT'ga hurmat, xato bo'lsa jimgina tashlaydi (UI'ga ta'sir qilmasin). Mavzu sahifasi, mashq javobi va qidiruvga ulansin.
- Admin → Statistika: eng ko'p ochilgan mavzular, xato foizi yuqori mashqlar (mavzuga havola bilan: "tushuntirishni yaxshila"), natijasiz qidiruvlar; oddiy jadval va yengil grafiklar.
Testlar: batch yuboruvchi, aggregatsiya UI. Playwright: sahifa ochish → statistikada ko'rinishi (aggregatsiyani qo'lda chaqirib).
Tayyor mezoni bo'yicha yakunla.
